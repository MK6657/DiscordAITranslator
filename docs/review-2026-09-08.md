# Follow-up review / 后续复查 · 2026-09-08

## 中文

在初始提交与安装器哈希修复之后，复查了 provider 请求/去重、设置读写与迁移、缓存持久化、诊断脱敏、输入框写入协调、自动翻译状态、安装器、发布检查和 CI。重点保护现有关键链契约，不做大规模重构。

确认并修复的问题：

1. **安装器预替换失败会误删原插件。** 当备份文件名冲突时，尚未创建备份也未覆盖目标，但 catch 分支会删除现有目标文件。现在记录是否实际完成替换，只回滚本次写入。新增固定时间戳备份冲突测试，确认原插件及旧备份逐字不变；同时覆盖首次安装后启用失败时删除新文件，以及已有插件覆盖后的回滚。
2. **请求重定向绕过初始目标限制。** 初始地址通过校验后，默认 fetch 自动跟随跳转；307/308 还可能转发消息正文与部分 provider 请求头。现在使用 redirect=error，在联系跳转目标前失败。用户须填写最终可信 API 地址，同源跳转也不例外。测试只连接本机 127.0.0.1 的两个临时 HTTP 服务，使用合成文本和假凭据，覆盖五类跳转；同时测试 src 入口和安装产物。
3. **CI 动作使用了产生弃用告警的旧版本。** 更新并锁定 checkout v7.0.1、setup-node v7.0.0 的完整提交 SHA；关闭 checkout 凭据持久化，设置 15 分钟作业超时。

前两项均先加入回归测试并在旧实现上复现失败，再实施修复。npm 依赖审计（包括开发依赖）在复查时报告 0 个已知漏洞；这不代表依赖或插件绝对安全。

## English

The follow-up inspected provider requests/deduplication, settings migration/persistence, caches, diagnostic redaction, composer write coordination, automatic-translation state, installer rollback, release gates, and CI. It preserves existing critical-chain contracts without broad refactoring.

Confirmed fixes:

1. A backup-name collision before replacement could enter installer cleanup and delete the original plugin. Rollback now requires an actual destination replacement by this installation. Fixtures verify preservation of the original plugin/backup, cleanup after a failed first install, and rollback after overwriting an existing plugin.
2. Fetch previously followed redirects after validating only the initial endpoint; redirects could forward message content or provider-specific headers. Requests now use redirect=error, and users must configure the final trusted URL directly. Real local-only HTTP fixtures exercise 301/302/303/307/308 against both source and generated artifact, with synthetic text and credentials.
3. CI actions emitted deprecated-runtime warnings. Upgrade to full-SHA-pinned checkout v7.0.1 and setup-node v7.0.0, disable persisted checkout credentials, and limit job runtime to 15 minutes.

The first two issues were reproduced by failing tests before their fixes. npm audit, including development dependencies, reported zero known vulnerabilities at review time; this is not proof of complete safety. The artifact hash above supersedes the initial intake baseline hash. Changes remain Unreleased under v0.2.0.

Validation gates are npm run release:check, isolated local regressions, and Windows Node 22/24 CI on the PR and main. Consult the corresponding Actions runs for cloud results. No real Discord account, UI flow, or provider was exercised; live-host compatibility and the absence of all defects cannot be guaranteed.
